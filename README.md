# ポートフォリオサイト

作品のフォルダを `works/` に入れるだけで、サイトが自動で組み上がります。
インストールは不要です(Mac 標準の Python だけで動きます)。

## 更新のしかた

ダブルクリックで使う `.command` ファイルは、`コマンド/` フォルダにまとめてあります(作品を追加・MVを追加・サイトを更新・イベントを追加・背景動画を追加・Spotifyリンクを追加)。以下で「○○.command」と書いてあるものは、すべてこのフォルダの中にあります。

### 方法1: ウィザードで追加(おすすめ)

1. `作品を追加.command` をダブルクリック
2. 聞かれることに答える(URLを貼る → タイトル → 表紙画像をドラッグ&ドロップ)
   - YouTube / Spotify のURLなら、タイトルと表紙は自動で取得されます
3. 最後に「サイトを更新しますか?」で Enter

### 過去の MV(YouTube の動画)を追加する

自動の取り込みは、チャンネルの新着(直近15本)だけが対象です。それより前の MV は、`MVを追加.command` をダブルクリックして、YouTube の URL を1行ずつ貼り付けます(何本でも。終わったら空 Enter)。

- タイトルと**公開日**、概要欄の**オフボーカルなどの配布リンク**は、動画のページから自動で読み取ります。サムネイルが表紙になります。
- すでにサイトにあるものは、飛ばします。以前に消した(または Trailer などで除外した)動画は、確認が出て、「y」で追加できます。
- 追加した MV は、同じ曲名の配信の作品(Apple Music など)と、自動で相互にリンクされます。
- 最後に「公開しますか?」で Enter を押すと、ビルドして公開まで行います。
- **プレイリストの URL**(`https://www.youtube.com/playlist?list=…`)を貼ると、その中の動画を、まとめて追加できます(公開されているプレイリストの先頭100本まで)。本数を確認してから追加します。Trailer など、`import.txt` の `youtube-exclude` に書いた言葉を含む動画と、以前に消した動画は飛ばします。プレイリストに他のチャンネルの動画が入っていることがあるので、載せたくないものは、その作品の `info.txt` に `draft: yes` と書くか、フォルダを消してください。
- **「案件」として追加する**(関わらせて頂いた作品など、自分のチャンネルではない動画): ウィザードで「分類」を聞かれたら `2` を選ぶか、ターミナルで `python3 add_youtube.py --type 案件 URL` と打ちます。Works に「案件」の絞り込みが付き、MV とは別の分類で並びます。案件の作品は、配信との自動リンクや BOOTH の紐づけはされません。すでにサイトにある動画は、そのままです(分類も変えたいときは `--reclassify` を付けます)。案件の長い題名は、自動で短くします(ハッシュタグ・「Official Music Video」などの注記・末尾の MV を除き、「○○に「曲名」を歌ってもらったよ」は「曲名(○○)」にします)。元の題名は、`info.txt` の `yt-title:` に残るので、題名を直したいときは `title:` を書き換えてください。`info.txt` に `type: 案件` と書いても、同じ分類になります。
- **概要欄の配信リンク(案件)**: 案件の動画は、概要欄にある配信・販売のリンク(Spotify の曲/アルバム・Apple Music・ニコニコ動画・Bandcamp・BOOTH・linkco.re / orcd.co / lnk.to のリンクまとめ)が、自動でボタンになります(同じサービスは最初の1つだけ。ユーザーやアーティストのページ、linktr.ee・lit.link・X・Instagram は対象外です)。すでに追加した案件には、`python3 add_youtube.py --refresh-links`(`--dry-run` を付けると、足す予定の一覧だけ表示)で、まとめて足せます。すでに同じサービスのリンクがある作品には足さず、手で足したリンクも消しません。追加する前に、リンクが切れていないか(404 など)を確かめて、切れているものは飛ばします。カバー動画の概要欄にある元の曲のリンクなど、合わないものがあったら、その作品の `info.txt` の `links:` から、その行を消してください。
- ターミナルなら `python3 add_youtube.py URL URL …`(`--dry-run` で確認だけ、`--force` で除外した動画も追加)。

### 方法2: フォルダを手で作る

`works/` の中に新しいフォルダを作り、`info.txt` と画像を入れます。

```
works/2026-10-01-新曲/
  info.txt      ← 必須
  cover.jpg     ← 表紙(なければ最初の画像、YouTubeならサムネイル、それもなければ自動の色面)
  photo1.jpg    ← 他の画像は作品ページのギャラリーになる
```

`info.txt` の書き方(`title` 以外は全部省略可):

```
title: 新曲タイトル
date: 2026-10-01
type: 音楽              ← 音楽 / 動画 / グッズ / その他。省略するとリンク先から自動判定
description: 一言説明
links:
https://open.spotify.com/track/...       ← URLだけでOK。ボタン名は自動
BOOTH: https://example.booth.pm/items/1  ← 名前を付けたいときは「名前: URL」
---
ここから下は自由なメモ(制作の裏話など)
```

- 下書きにしたいとき: `draft: yes` と書く、またはフォルダ名の頭に `_` を付ける
- 作品を消す: フォルダごと削除
- 並び順は日付の新しい順。日付を省略するとフォルダ名の頭(2026-10-01-…)から読みます

### 自動で埋め込みプレーヤーになるリンク

YouTube / Spotify / Apple Music / SoundCloud / ニコニコ動画。
それ以外(BOOTH・Amazon・Bandcamp など)はボタンになります。

## サイトを作り直す

`サイトを更新.command` をダブルクリック。`docs/` フォルダが作り直されます。
(ターミナルなら `python3 build.py`)

## サイト全体の設定

`site.txt` に次のことを書きます。最初に一度だけでOKです。

- `name` / `tagline` / 自己紹介(`---` の下)
- `menu:` … 左のメニューに「Works」「About」に続いて並ぶ項目(通販ページなど)
- `links:` … メニューの下に小さく並ぶリンク。X・Instagram などは1行目、Spotify・Apple Music・ニコニコ・bilibili などの音楽サービスは2行目に、自動で分かれて並びます(順番は、ここに書いた順です)
- `contact:` … メニューの末尾に出る「Contact」の行き先(メールアドレスかURL。空なら項目なし)
- `logo:` … ロゴ画像のファイル名(このフォルダに置く)。空なら名前を文字で表示
- `og-image:` … URL を SNS・Discord などに貼ったときに出る画像のファイル名(このフォルダに置く。横長 1200×630 が目安)。トップページに使われます。空なら、いちばん新しい作品の表紙になります。作品ページは、それぞれの表紙です。貼ったあとに変えても、Discord や X は前の画像を覚えていることがあります(しばらく待つか、URL の最後に `?v=2` を付けて貼り直すと、新しく読み込まれます)。
- `background:` … トップページの背景動画。空なら Works に入れたYouTube動画をシャッフルして流す。URLなら1本に固定、`off` で無し
- `mosaic:` … 背景動画のモザイクの大きさ(px)。大きいほど粗い。0でモザイクなし
- `mosaic-style:` … `pixel` は隙間のない四角いブロックの本物のモザイク(自前クリップのときだけ。動画を縮小して描きます)、`grid`(初期値)は格子状の線を重ねる方式
- `form:` … 依頼受付フォームのURL(Google フォームなど)。空なら、メールの下書きを作る内蔵のフォーム

見た目を変えたいときは `theme/style.css`。先頭の `:root` の色(`--main` がボタンやバッジの青)を変えれば全体が変わります。

## トップページと Works

トップは、左に名前とメニュー、右に Works の文字リスト(日付・タイトル・種類)を置き、背景に動画が流れます。
リストの行にカーソルを乗せると、その作品のジャケットがリストの右隣に出ます(スマホでは出ません)。種類(Streaming / MV)での絞り込みボタンつき。
右側は、メニューの「Works」「Events」「Contact」で開閉するパネルです。1つ開くとほかは閉じ、開いているものをもう一度押すと全部閉じて、背景の映像だけを見られます(「−」が開いている状態、「+」が閉じている状態。ブラウザが覚えています)。
リストの見た目は `style.css` の `.works-list` / `.row`、ジャケットの表示は `.peek` と `fx.js` です。

## 演出について

動きの部分は `theme/fx.js`(動作)と `theme/style.css`(見た目)にあります。

- **紙のようなざらつき**: 全体に薄いノイズを重ねています。濃さは `style.css` の `body::after` の `opacity`(0で無し)。
- **フェードイン / ページ遷移**: 開くと順にふわっと現れ、リンクを押すと暗転してから移動します。
- **レンズ**: 背景動画が表示されているときだけ、カーソルの周りが「レンズ」になります(下の背景動画を参照)。背景動画がないページには、カーソルを追う丸は出ません。
- **クリックの波紋**: 背景動画が表示されているとき、画面をクリックすると、その場所から円が波紋のように広がり(大きさと速さは、fx.js の RIPPLE_R と RIPPLE_MS で変えられます)、円の内側はモザイクが外れて元の映像が見えます(広がっている間は内側もそのまま。終わり際だけ、円全体がいっせいにモザイクへ戻ります。同時に3つまで重なります)。先端には光の細い輪が出ます。ボタンやリンク、入力欄の上では出ません。広がる大きさ(px)は `fx.js` の `RIPPLE_R`、速さ(ミリ秒)は `RIPPLE_MS` で変えられます。
- **ジャケットの傾き**: 作品ページの大きなジャケットが、カーソルの方向に傾きます。
- **背景動画**: トップページの背景で、動画が(開くたびに順番をシャッフルして、1本ずつ)流れ、終わると次の動画に切り替わります。自前のクリップ(下の「背景動画のクリップを作る」)があればそれを、なければ Works の YouTube 動画を流します。音は出ません(無音です)。タイルの格子と背景色のかぶせで、文字が読めるようにしています。かぶせの濃さは `style.css` の `.bgvideo` の `--dim`(小さいほど動画がはっきり見える)。
  - **文字色の自動調整**: 背景動画が表示されている間、メニューとリストの文字は「背景が明るい所は暗く、暗い所は明るく」自動で変わります(CSS の `mix-blend-mode: difference`)。YouTube の映像は外部のものなのでピクセルを読み取れず、色の反転で近似しています。背景が中間の明るさ(灰色)のところでは読みにくくなることがあります。やめたいときは `style.css` の「文字色を背景に合わせて変える」ブロックを消してください。
  - **レンズ**: カーソルの周りだけモザイクとかぶせが消えて、映像がクリアに見えます。メニュー・Works のリストなど文字そのものの上ではレンズが閉じ(文字の横の余白では開き)、読みやすさを保ちます。大きさは `fx.js` の `LENS_R`、閉じる場所は `READING` で変えられます。

スマホなどマウスのない端末と、OSで「視差効果を減らす」を設定している環境では、遷移のフェード・マウス追従・背景動画は自動で無効になります(通信量の節約にもなります)。
演出が不要なら、`build.py` の `fx.js` を読み込む行を消せばOKです。

背景に使う動画は、埋め込みが許可されているもの(自分で公開した動画など)にしてください。

## Events(イベント出演の予定)

`events.txt` に1行ずつ「日付 | イベント名 | 場所 | 詳細のURL」を書くと、トップの「Events」に出ます(URLと場所は省略可)。URL を書いたイベントは、日付・名前・場所の上も含めて、行全体がリンクになります(新しいタブで開きます)。
`イベントを追加.command` をダブルクリックして、質問に答えて追加することもできます(最後に公開まで進めます)。
日付が過ぎたものは、「過去の出演」に自動で移ります(サイトは毎日自動で作り直されます)。

## Guideline(二次利用ガイドラインの要点)

メニューの「Guideline」を押すと、ガイドラインの要点のパネルが開きます。中身は `guideline.txt` です。`## 見出し` の下に、1行1項目で書き、`link:` に全文(note)のURLを書くと、パネルの一番上に「全文を読む」リンクが出ます。書き換えて「サイトを更新」するだけで反映されます。`site.txt` のメニューの `Guideline: #guideline` を外す(または `guideline.txt` を消す)と、項目は出なくなります。note の全文を直したときは、要点も合わせて直してください。

## 依頼受付フォーム(Contact)

メニューの「Contact」を押すと、依頼受付フォームのパネルが開きます。

- **フォームから直接送る(Web3Forms)**: `site.txt` の `form-key:` に Web3Forms のアクセスキーを入れると、「この内容で送信する」ボタンで、フォームから直接メールが届きます(メールアプリは要りません)。キーは https://web3forms.com で、受け取りたいメールアドレスを入れると、メールで届きます(無料枠あり。登録時に、月の送信数などの条件を確認してください)。キーは公開されても問題のない種類なので、`site.txt` に書いて構いません。送信できなかったときは、画面にそう表示され、「メールアプリで下書きを作る」ボタンから送れます。キーが空のあいだは、これまでどおり、メールの下書きを作る方式です。スパム対策として、人には見えない欄(ボットが入力すると弾かれる)を入れてあります。
- **いまのフォーム**: ご依頼の内容(楽曲制作 / 編曲 / MIX・Mastering / イベント出演 / その他)を選べるフォームです。「MIX・Mastering」を選んだときだけ、料金表(`pricing.txt`)のプラン・オプション・料金表・見積りの目安が現れます。お名前・返信先・ご依頼の内容・希望納期(カレンダーで選びます。未定のときは「日付は未定・相談したい」にチェック)・詳細(オプション以外は、すべて必須。MIX・Mastering のときはプランも必須)を入力して「メールの下書きを作る」を押すと、メールアプリが開いて、入力内容(お見積りの目安つき)が下書きされます(送信はメールアプリで行います)。宛先は `site.txt` の `contact:` のメールアドレスです。
- **料金表と見積りの目安**: 「MIX・Mastering」を選ぶと出る「料金表を見る(税込)」を開くと、プラン・オプション・注意事項が見られます。プランとオプションを選ぶと、お見積りの目安(税込)が自動で出ます(金額が決まっていないプランは「ご相談」)。**料金や選択肢を変えたいときは、`pricing.txt` の数字や項目を書き換えるだけ**です(書き方はファイルの先頭に書いてあります)。オプションは、選んだプランで選べるものだけが出ます(いまは、Mastering / 単体プランでは「DDP書き出し」だけ、それ以外のプランでは「生ドラムMIX」「ボーカルエディット」)。どのプランで選べるかは、`pricing.txt` の各 option 行の最後の「対象」で決めています。目安は確定ではなく、正式なお見積りは内容を確認してから連絡する前提の表示です。
- **見た目のしくみ**: フォームの一番上に、入力の進み具合のバーが出ます(必須項目が埋まるほど伸びます)。見積りの目安は、プランやオプションを変えると、数字がカウントして切り替わります。送信できたら、入力欄が消えて「Thank you / 送信完了」と、送信した内容が出ます「控えをメールで受け取る」を押すと、入力されたメールアドレス宛の下書きがメールアプリで開きます(送信すると控えになります)。(「もう一度入力する」で戻れます)。
- **Google フォームなどを使う(おすすめ)**: メールアドレスを画面に出さず、返信や管理もしやすくなります。Google フォームで「依頼受付フォーム」を作り、その公開URLを `site.txt` の `form:` に書くと、Contact のパネルにそのフォームが埋め込まれます(回答はあなたのメールやスプレッドシートに届きます)。

## BOOTH とサービスのボタン色

- `import.txt` の `booth:` にショップのURLを書くと、ショップの全商品が `booth-items.json` に保存され(毎日自動で更新)、商品名に作品名(別名も)が入っている作品のページに「BOOTH」のボタンと商品の一覧が出ます。**関連する作品**(同じ曲を含む作品)のページにも、関連する商品(CD など)が出ます。合わない商品は、作品の `info.txt` に `booth: 商品ID` を書いて紐づけられます。
- 作品ページのボタンは、Apple Music(赤)・Spotify(緑)・YouTube(赤)・ニコニコ動画(黒)・BOOTH(朱色)など、サービスのイメージカラーになります(色は `style.css` の `.btn[data-svc=…]`)。

## スマホの表示

画面の幅が約760px以下(スマホ)のときだけ、表示が変わります(パソコンでは変わりません)。

- **メニューは開閉式**: 最初は、名前と「MENU」ボタンだけが出ます。「MENU」を押すと、メニュー(Works・Events・…とSNS)が開きます。Works・Events・Guideline・Contact を選ぶと、メニューが閉じて、そのパネルまで自動でスクロールします。外部サイト(Spotify など)を選んだときは、新しいタブで開きます。
- **依頼フォームは、指で入力しやすく**: 入力欄は文字を16px、高さを約52pxにして(iPhone で入力時に画面が拡大されるのを防ぎます)、チェックボックスは24px、「送信する」「メールアプリで下書きを作る」は、横幅いっぱいの大きなボタンです。
- 見た目は、`theme/style.css` の `@media (max-width: 760px)` のところで変えられます。

## 右側のパネルの最初の表示

ページを新しく開いたとき(URL を開く・リンクを押す)は、いつも **Works** が開きます。再読み込みと、ブラウザの「戻る」のときだけは、前に開いていたパネルを引き継ぎます。`https://…/#contact` のように、URL の最後にパネル名(`#works`・`#events`・`#guideline`・`#contact`)を付けると、新しく開いたときも、そのパネルが開きます。

## Works の一覧(年のタブ)

トップの Works は、年ごとのタブが横に並び、選んだ年の作品だけが出ます(最初はいちばん新しい年。タブの右の数字は、その年の作品数)。タブが画面に入りきらないときは、横にスワイプ(PC は横スクロール)できます。「Streaming」「MV」「案件」で絞り込むと、件数が数え直され、該当のない年のタブは薄くなって選べなくなります(選んでいた年に該当がないときは、該当のある最新の年に移ります)。年は、作品の `date:` で決まります。

JavaScript が使えない環境では、タブにならず、年ごとの折りたたみ(いちばん新しい年だけが開いた状態)のまま表示されます。

## 見出し文と関連作品

- **MV と配信(Streaming)の相互リンク**: MV の公開や配信の開始を、手でつなぐ必要はありません。同じ曲名の作品どうし(MV「曲名」と、配信の収録曲)が、毎日の取り込みとビルドで、自動で「関連作品」として相互にリンクされます。BOOTH の商品も、商品名に曲名が入っていれば、配信の作品にも MV にも付きます。曲名の表記が違うとき(Apple は「Gestalt」、YouTube は「姿」など)だけ、`info.txt` に `aliases:` を書いてください。

- **見出し文**: 音楽の作品には「シングル「レゴリス」を配信開始しました」、動画には「「レゴリス」のMVを公開しました」のような見出しが、一覧と作品ページに自動で付きます。自分で書きたいときは、その作品の `info.txt` に `headline: 好きな文章` を書くと、そちらが使われます。
- **作品ページの内容**: 見出し・名義・作品名(Apple 上の原題つき)・リンクボタンとその下の収録曲・埋め込みプレーヤー・関連作品。
- **収録曲の並び**: 6曲ごとに右の列へ改行します(曲数が6以下なら1列)。画面に入りきらない幅では、収録曲のところだけ横にスクロールできます。6曲を変えたいときは、`style.css` の `.tracks ol` の `--rows: 6` を直します。
- **別名**: 同じ作品に別の名前がある場合(例: Apple では「Gestalt」、Spotify では「姿」)は、`info.txt` に `aliases: 姿` と書くと、作品ページに「別名」として出て、Spotify リンクの照合にも使われます。
- **関連作品の相互リンク**: 同じ曲を含む作品どうし(例: シングル「レゴリス」・EP「Gestalt」・MV「レゴリス」)が、お互いのページにリンクされます。曲名はAppleの収録曲と動画のタイトルから自動で判定します。判定されないものを結びたいときは、`info.txt` に `related: 相手のフォルダ名の頭(2025-09-03 など)` や `related: 相手の作品名` を書いてください(カンマ区切りで複数可。書いた側と相手の両方に表示されます)。
- **Spotify のリンク**: Apple Music の作品に、Spotify のアルバムのリンクを付けられます(下の「Spotify のリンク」)。音楽の埋め込みプレーヤーは、Spotify があれば Spotify の1つだけを出します。
- **ニコニコ動画などのリンク**: `info.txt` の `links:` に `ニコニコ動画: URL` のように1行ずつ書くと、作品ページのボタンになります(ニコニコ動画は埋め込みプレーヤーも付きます)。

## 背景動画のクリップを作る(広告・字幕なし)

YouTube の埋め込みは、広告や自動字幕が出ることがあります。自分の動画から短いクリップを作ってサイトに置くと、それらが出ず、読み込みも軽くなります。

1. MV の動画ファイルを用意します(元データ、または YouTube Studio の「ダウンロード」で保存したもの)。
2. `背景動画を追加.command` をダブルクリックし、動画をドラッグ&ドロップ → どの作品の背景にするか選ぶ → 切り出し開始位置(例 `1:05`)と長さを入力します。480p・約20秒の小さなクリップ(1本 1〜3MB程度)が、その作品のフォルダに `bg.mp4` として入ります。
3. 最後に「公開しますか?」で Enter を押すと、公開まで進みます。
4. クリップは、ランダムな順で再生され、全部流れたらシャッフルし直して、ずっとループします。クリップの間はクロスフェードでつなぐので、背景の動画は途切れません(音は出ません)。
5. **1つの作品に何本でも**置けます。すでにクリップがある作品を選ぶと、「追加(bg-2.mp4 など)か、上書きか」を聞かれます。アルバムの収録曲ごとにクリップを作る、といった使い方ができます。
6. 動画の上下左右に黒帯(レターボックス)があれば、自動で切り落とします。
7. クリップを消したい作品は、`works/<作品>/bg.mp4` や `bg-○○.mp4` を削除してください。

- ffmpeg が必要です(この Mac には入っています。なければ `brew install ffmpeg`)。
- Mac で `python3 add_bgclip.py 動画.mp4 --work 3 --start 1:05 --length 20` のようにも実行できます(番号は一覧の番号)。`--slug 作品のフォルダ名` で作品を指定でき、`--name 名前` を付けると `bg-名前.mp4` として追加できます。
- クリップが1本もなければ、これまでどおり YouTube の動画を流します。YouTube を使わず自前クリップだけにしたいときは、`site.txt` の `background:` はそのまま(空)で、クリップを作ってください。
- 容量の目安: 1本 0.5〜2MB程度(場面の動きが多いほど大きくなります)。10本でも20MBほどで、GitHub の上限(サイト全体で1GB 程度)には余裕があります。

## リンク切れの検知

`check_links.py` が、サイトに載せているリンク(作品のボタン・BOOTH・メニュー・SNS・Events・Guideline)を調べます。毎週月曜の朝に GitHub が自動で実行し、**切れているリンクがあれば、GitHub に「リンク切れの確認が必要です」という Issue が立ち**(担当がオーナーなのでメールに通知が届きます)、直ったあとの確認で問題がなければ、自動で閉じます。Mac で `python3 check_links.py` と打つと、今すぐ調べられます。

- **切れている**: 404 / 410、ドメインがない、YouTube・Spotify の動画/アルバムが見つからない。
- **要確認**: ボット対策でブロックされたもの(403 など)。実際には見られることが多いので、Issue にはせず、結果の表示だけに出します。

## 素材(オフボーカルなど)のリンク

YouTube の概要欄に「OffVocal / 歌詞 - https://…」のような行(オフボーカル・素材・ダウンロード・配布などの言葉と URL の組)があれば、取り込みのときに、その作品のボタンとして自動で付きます(自動で取り込んだ MV が対象。すでにある作品にも、次の取り込みで足されます)。概要欄にない素材は、`info.txt` の `links:` に `名前: URL` で足せます。

## 検索エンジン向けの整備(自動)

ビルドのたびに、`sitemap.xml`(トップと全作品ページ)と、各ページの構造化データ(音楽は MusicAlbum、動画は VideoObject)、canonical のリンクを自動で作ります。`site.txt` の `url:` が元になるので、空にしないでください。Google に早く見つけてもらうには、Google Search Console にサイトを登録して、`https://（サイトのURL）/sitemap.xml` を送信します(任意。登録はご自身のアカウントで行います)。

## 新着の自動取り込み(Apple Music / YouTube)

`import.txt` に Apple Music のアーティスト、YouTube のチャンネルを書いておくと、新しいリリースや動画が `works/` に自動で追加されます。APIキーは不要です。

- **いつ動くか**: GitHub が毎日(日本時間の朝6時台)自動で確認し、新着があれば追加して公開します。`サイトを更新.command` を押したときや、GitHub の「Actions」タブから手動で実行したときにも確認します。
- **取り込まれるもの**: Apple Music は作品名(Apple に登録された日本語表記の曲名)・種別(シングル/EP/アルバム)・収録曲・発売日・ジャケット・リンク、YouTube はタイトル・公開日・リンク(サムネイルは自動)。YouTube に動画が入ると、背景動画の候補にもなります。
- **目印**: 取り込まれた作品の `info.txt` には `auto: yes` と `source:` が入ります。
- **載せたくない作品**: その `info.txt` に `draft: yes` と書くか、フォルダごと消します。消しても、`works/.imported.txt` に記録が残るので、復活しません。
- **手で直す**: 取り込まれた作品も普通の作品フォルダです。タイトルや説明を直したり、Spotify などのリンクを `links:` に足したりできます(自動で上書きはしません)。
- **設定**: Apple Music は `apple:`(アーティストページのURL)、YouTube は `youtube:`(チャンネルのURLか UC から始まるID)。ショート動画は `youtube-shorts: yes` で取り込めます。タイトルに特定の言葉を含む動画は、`youtube-exclude:` で除外できます(いまは Trailer と Teaser)。
- **Mac で試す**: `python3 import_works.py --dry-run` で、何が取り込まれるかだけ確認できます。

### 新作の通知

自動で新しい作品などが取り込まれると(Apple Music・YouTube の新着、Spotify のリンク付け、BOOTH の新商品)、GitHub に「新着を取り込みました」という **Issue** が自動で立ち、担当がオーナーになるので、GitHub に登録したメールに通知が届きます。Issue には、新しい作品のページへのリンクが入っています。タイトルや説明を直したいときは、`works/<フォルダ名>/info.txt` を編集して push してください。

**Discord にも通知したいとき**(任意): Discord のサーバーで「チャンネルの設定 → 連携サービス → ウェブフック」を作り、そのURLを、GitHub のリポジトリの「Settings → Secrets and variables → Actions → New repository secret」に、名前 `DISCORD_WEBHOOK_URL` で登録します。登録すると、次の自動実行から Discord にも届きます(登録しなければ、Discord には送りません)。通知に失敗しても、サイトの公開は止まりません。

注意: Apple Music のアーティストページに載っている作品は、他のアーティスト名義のもの(フィーチャリング参加など)も取り込まれます。不要なものは上の方法で外してください。
GitHub の定時実行は、リポジトリに60日以上動きがないと止まることがあります(Actions タブから再開できます)。

## Spotify のリンク

Apple Music の作品に、対応する Spotify のアルバムのリンクを付けます(作品ページのボタンと埋め込みプレーヤーになります)。

- **新作が出たとき**: Apple Music から作品が自動で取り込まれたあと、Spotify のアプリやサイトで、そのアルバムの「共有 → リンクをコピー」をして、`Spotifyリンクを追加.command` をダブルクリックして貼り付けます(複数まとめて貼れます)。アルバム名から対応する作品を見つけて、リンクを付けます。最後に「公開しますか?」で Enter を押すと公開まで進みます。Mac で `python3 add_spotify.py URL` でも同じです。
- **見つからないとき**: 「対応する作品が見つかりません」と出た場合は、Spotify と Apple Music でアルバム名が違うか、その作品がサイトにありません。作品の `info.txt` の `links:` に `Spotify: URL` を直接書いてください。
- **自動化(任意・Premium が必要)**: Spotify の公式 API を使うと、完全に自動で付きます。ただし開発者アプリの作成に Spotify Premium が必要です。使う場合は、アプリの Client ID と Client Secret を、GitHub の Secrets(`SPOTIFY_CLIENT_ID` / `SPOTIFY_CLIENT_SECRET`)に登録してください(`gh secret set SPOTIFY_CLIENT_ID --repo bcno01/home` のように実行すると、値の入力を求められます)。キーは **リポジトリのファイルに絶対に書かないでください**(公開されます)。登録しなければ、この自動処理は何もしません。

## 公開のしくみ(GitHub Pages + 自動ビルド)

`works/` や `site.txt` を変えて GitHub に push すると(定時の自動取り込みでも)、GitHub 側が自動でサイトを作り直して公開します(`.github/workflows/pages.yml`)。
`docs/` は自分のMacでの確認用で、GitHub には載せません(`.gitignore` で除外)。

- いつもの更新: `作品を追加.command` で作品を足し、`サイトを更新.command` をダブルクリック(確認用ビルド → push)。反映まで1〜2分。
- Macがなくても、GitHub のサイト上で `works/` にフォルダやファイルをアップロードすれば、同じように公開されます。
- うまく公開されないときは、GitHub のリポジトリの「Actions」タブでエラーを確認できます。

注意:
- 作品の日付は、`info.txt` の `date:` か、フォルダ名の頭(`2026-10-01-…`)で必ず指定してください(`作品を追加.command` で作ったものは自動で入ります)。
- 写真は jpg / png / webp / gif / svg。iPhone の HEIC 形式は表示できないので、jpg に変換してください。
- `works/` と `site.txt` の中身は、そのまま公開されます(リポジトリが公開のため)。メールアドレスなど、載せたくない情報は書かないでください。
